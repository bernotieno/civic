# 🚀 CivicAI Production Deployment Guide

## Render.com Deployment

### Prerequisites
- GitHub repository with your code
- Render.com account

### Quick Deploy (Recommended)

1. **Fork/Clone Repository**
   ```bash
   git clone https://github.com/your-username/civicAI.git
   cd civicAI
   ```

2. **Deploy to Render.com**
   - Go to [Render.com](https://render.com)
   - Click "New" → "Blueprint"
   - Connect your GitHub repository
   - Select the `render.yaml` file
   - Click "Apply"

### Manual Deployment Steps

#### 1. Backend (Django API)

1. **Create Web Service**
   - Service Type: Web Service
   - Environment: Python 3
   - Build Command: `./build.sh`
   - Start Command: `gunicorn civicAI.wsgi:application`

2. **Environment Variables**
   ```
   DJANGO_SETTINGS_MODULE=civicAI.settings.production
   ENVIRONMENT=production
   DEBUG=false
   SECRET_KEY=[Auto-generated by Render]
   DATABASE_URL=[From PostgreSQL service]
   REDIS_URL=[From Redis service]
   ALLOWED_HOSTS=your-backend-url.onrender.com
   CORS_ALLOWED_ORIGINS=https://your-frontend-url.onrender.com
   TIME_ZONE=Africa/Nairobi
   ```

#### 2. Frontend (React/Vite)

1. **Create Web Service**
   - Service Type: Web Service
   - Environment: Node
   - Build Command: `cd frontend && npm ci && npm run build`
   - Start Command: `cd frontend && npm run start`

2. **Environment Variables**
   ```
   VITE_API_URL=https://your-backend-url.onrender.com
   NODE_ENV=production
   ```

#### 3. Database (PostgreSQL)

1. **Create PostgreSQL Database**
   - Database Name: `civicai_production`
   - User: `civicai_user`

#### 4. Cache (Redis)

1. **Create Redis Service**
   - Plan: Free (256MB)

### Post-Deployment Setup

1. **Run Initial Setup**
   The build script automatically runs:
   - Database migrations
   - County setup
   - Superuser creation
   - Static file collection

2. **Access Your Application**
   - Backend API: `https://your-backend-url.onrender.com`
   - Frontend: `https://your-frontend-url.onrender.com`
   - API Documentation: `https://your-backend-url.onrender.com/api/docs/`

### Environment Variables Reference

#### Required Backend Variables
```bash
# Core Django Settings
SECRET_KEY=your-secret-key
ENVIRONMENT=production
DEBUG=False
DJANGO_SETTINGS_MODULE=civicAI.settings.production

# Database & Cache
DATABASE_URL=postgresql://user:pass@host:port/db
REDIS_URL=redis://host:port/0

# Security
ALLOWED_HOSTS=your-domain.onrender.com
CORS_ALLOWED_ORIGINS=https://your-frontend.onrender.com
SECURE_SSL_REDIRECT=True

# Localization
TIME_ZONE=Africa/Nairobi
```

#### Optional Backend Variables
```bash
# Email (if needed)
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=your-email@gmail.com
EMAIL_HOST_PASSWORD=your-app-password

# AI Features (if using)
OPENAI_API_KEY=your-openai-key
CLAUDE_API_KEY=your-claude-key
AI_SENTIMENT_ANALYSIS_ENABLED=True
AI_URGENCY_SCORING_ENABLED=True
```

#### Frontend Variables
```bash
VITE_API_URL=https://your-backend-url.onrender.com
NODE_ENV=production
```

### Monitoring & Maintenance

1. **Health Checks**
   - Backend: `https://your-backend-url.onrender.com/api/health/`
   - Database connectivity is automatically monitored

2. **Logs**
   - View logs in Render.com dashboard
   - Backend logs include Django, user, and AI activity

3. **Updates**
   - Push to main branch triggers automatic redeployment
   - Database migrations run automatically

### Troubleshooting

#### Common Issues

1. **Static Files Not Loading**
   - Ensure `STATIC_ROOT` is set correctly
   - Check WhiteNoise configuration
   - Verify `collectstatic` runs in build

2. **Database Connection Issues**
   - Verify `DATABASE_URL` format
   - Check PostgreSQL service status
   - Ensure migrations completed

3. **CORS Errors**
   - Verify `CORS_ALLOWED_ORIGINS` includes frontend URL
   - Check frontend `VITE_API_URL` points to backend

4. **Build Failures**
   - Check build logs in Render dashboard
   - Verify all dependencies in `requirements.txt`
   - Ensure Python version compatibility

### Performance Optimization

1. **Database**
   - Connection pooling enabled by default
   - Consider upgrading PostgreSQL plan for production

2. **Caching**
   - Redis caching configured for sessions and AI results
   - Consider upgrading Redis plan for high traffic

3. **Static Files**
   - WhiteNoise serves static files efficiently
   - Consider CDN for media files in high-traffic scenarios

### Security Checklist

- ✅ DEBUG=False in production
- ✅ SECRET_KEY is secure and unique
- ✅ HTTPS enforced (SECURE_SSL_REDIRECT=True)
- ✅ CORS properly configured
- ✅ Database credentials secured
- ✅ Environment variables not in code
- ✅ Admin interface secured
